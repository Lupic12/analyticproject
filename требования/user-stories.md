# User Stories

User Story — короткое описание потребности пользователя: «Как [роль], я хочу [действие], чтобы [цель]».

| ID | User Story | Требование |
|---|---|---|
| US-01 | Как покупатель, я хочу выбрать товары и оформить заказ, чтобы купить их через интернет. | REQ-01 |
| US-02 | Как менеджер, я хочу видеть список заказов, чтобы знать, какие нужно обработать. | REQ-02 |
| US-03 | Как менеджер, я хочу менять статус заказа, чтобы отражать этап его обработки. | REQ-03 |
| US-04 | Как складской сотрудник, я хочу видеть и обновлять остатки товаров, чтобы знать, что есть в наличии. | REQ-04 |
| US-05 | Как менеджер, я хочу видеть статус оплаты, чтобы понимать, оплачен ли заказ. | REQ-05 |
| US-06 | Как курьер, я хочу видеть назначенные доставки и менять их статус, чтобы выполнять доставку. | REQ-06 |
| US-07 | Как владелец, я хочу видеть отчёт по заказам и продажам, чтобы оценивать работу магазина. | REQ-07 |

## Критерии приёмки User Stories

| История | Условия проверки |
|---|---|
| US-01 | Заказ получает номер и сохраняется; система проверяет остатки и сообщает о нехватке товара. |
| US-02 | Менеджер видит номер, дату, сумму и статус заказа и может открыть подробности. |
| US-03 | Менеджер меняет статус; новый статус сохраняется и отображается. |
| US-04 | Остаток товара отображается и обновляется; отрицательное количество не принимается. |
| US-05 | В заказе отображаются сумма и статус оплаты. |
| US-06 | Курьер видит только назначенные доставки и может обновить их статус. |
| US-07 | Владелец выбирает период и видит число заказов и общую сумму продаж. |
